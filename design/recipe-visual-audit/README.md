- 203 个烹饪步骤保留对应原图，32 个备菜步骤补上对应来源图片。原素材缺图时显示文字提示：花生鲍汁凤爪的 6 步、辣咖喱牛排骨的焯水、清蒸鲈鱼的擦干抹油架鱼，共 8 个烹饪步骤不再展示错阶段照片。其余 37 个备菜步骤亦明确缺图，不回退到成品。
- 封面独立选择成品；修复冰箱、空盘、烤箱、人物讲解等错误封面。芦笋重新对齐腌制/沥汁/煎制图片，大骨头汤和三明治的多格图分拆到对应步骤。

`review.html` 为全部图片与正文并列核对页，`report.json` 为逐菜统计。`timer-controls.png` 和 `full-image.png` 是 iOS 26.2 模拟器实际截图。

## 代码修复

图片组件改为保持比例完整展示，做饭图从 115 点增至 230 点。保留图片不截获触控的既有修复。做饭横向卡片使用非懒加载高度布局，让计时区变高时外层纵向滚动范围同步变化，并留出底部间距。

备菜与烹饪插图分开保存并按正文关联；缺图不回退成品。离线下载现在包括备菜图片。内置缓存返回显式封面，不再强取最后一步。

视频导入使用格式版本 4：提取动作及实际可见依据 → 独立选择成品 → 按食物和操作范围裁切并保持比例 → 第二次独立请求检查实际裁切后的图文。检查缺项、错阶段或封面不符会触发重新选帧，最多重试一次；仍不通过则导入失败。缺少真实过程图允许明确留空，不强行凑图。此流程增加一次模型调用及对应延时/费用。

## 重建

使用带 Pillow 的 Python 运行 `scripts/apply_recipe_visual_audit.py`（需要忽略目录中的原始素材），随后运行 `scripts/bundle_ios_recipes.py`、`scripts/recipe_visual_review.py` 和 `scripts/generate_xcode_project.py`。

`build_local_recipe_batch.py` 在重建后自动应用审核记录；打包脚本拒绝已审核菜谱回退为旧格式或错位数组。原始视频与含临时链接的笔记元数据不加入仓库。
